A fraqueza está no multicoluna e em cabeçalho/rodapé. O LayoutReader é um modelo treinado justamente para ordenar caixas de linha (LayoutLMv3 afinado no ReadingBank; é o ordenador que o MinerU usa). Os pesos já estão em models/terceiros/layoutreader/ (hantian/layoutreader, licença CC BY-NC-SA 4.0: uso acadêmico; cite isso no relatório). Rode em CPU.

Como usar o modelo (referência de uso; CONFIRA com um teste sintético de duas colunas antes de confiar):
  from transformers import LayoutLMv3ForTokenClassification
  modelo = LayoutLMv3ForTokenClassification.from_pretrained("models/terceiros/layoutreader").eval()
  # caixas: lista de [x0, y0, x1, y1] inteiros, cada coordenada normalizada para 0..1000 pela largura/altura da página; no máximo 510 caixas por página
  bbox = [[0, 0, 0, 0]] + caixas + [[0, 0, 0, 0]]
  input_ids = [0] + [3] * len(caixas) + [2]          # CLS, UNK para cada caixa, EOS
  attention_mask = [1] * len(input_ids)
  logits = modelo(bbox=tensor([bbox]), input_ids=tensor([input_ids]), attention_mask=tensor([attention_mask])).logits[0]
  logits = logits[1:len(caixas) + 1, :len(caixas)]    # linha i = caixa i; coluna j = posição j na leitura
  # decodificação: cada caixa escolhe a posição de maior logit; em conflito, fica quem tem o maior logit e as outras vão para a sua próxima opção, até não haver posição repetida. O resultado é a posição de leitura de cada caixa.
Se a página tiver mais de 510 linhas, descreva e teste a sua solução (por exemplo, fundir linhas vizinhas da mesma coluna em parágrafos antes de ordenar).
